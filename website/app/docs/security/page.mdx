# MiniGit Security Model & Safety Boundaries

## 1. Overview & Threat Model

MiniGit is a version control system implemented in C++20. As a tool handling untrusted repository archives, network pack streams, and user-supplied filesystem structures, it enforces specific security boundaries to prevent host compromise.

MiniGit is designed with defense-in-depth principles focused on three attack surfaces:
1. **Malicious Repository Trees & Path Traversal (Arbitrary File Overwrite)**
2. **Untrusted Network Payloads (pkt-line and packfile decoding)**
3. **Storage Corruption & Incomplete Writes (Data Integrity)**

---

## 2. Path Traversal & Filesystem Boundaries

### Path Traversal Defense (`minigit::core::resolve_safe_repo_path`)
Git repositories unpacked from untrusted remote clones, branches, or submodules can contain malicious path components designed to escape the repository directory tree (`../../etc/shadow` or `..\..\Windows\System32`).

MiniGit validates all relative paths across `checkout`, `clone`, `pull`, `clean`, `submodule`, and `worktree` operations using `is_safe_repo_relpath()` ([path_safety.cpp](file:///C:/Users/sagar/dev/cpp/projects/minigit/src/core/path_safety.cpp)):
- **Rejection of Absolute Paths & Drive Letters:** Paths starting with `/`, `\`, or Windows drive letters (e.g., `C:`) are rejected immediately.
- **Null Byte Detection:** Paths containing embedded `\0` bytes are dropped.
- **Component Traversal Walk:** Any token equal to `..` is rejected prior to lexical normalization.
- **Lexical Normalization Check:** `std::filesystem::path::lexically_normal()` is evaluated; any prefix matching `../` or targeting `.` / `..` triggers an immediate security violation (`std::runtime_error`).
- **Internal Metadata Protection:** Paths targeting `.minigit` or `.git` (or subdirectories within them) are strictly rejected from working tree checkouts to prevent malicious tampering with repository hooks, config, or HEAD refs.

### Atomic File Writes
To prevent repository state corruption during interrupted operations (e.g., power failure, SIGINT), critical metadata and object writes follow an atomic staging pattern:
- Objects and references are written to a temporary sibling file (`<target>.tmp.<pid>`).
- Once write and zlib stream flushing succeed, the file is atomically renamed into place via `std::filesystem::rename()`.

## 3. Network Transport & Parser Hardening

### Git Smart HTTP Protocol (`pkt-line`)
Network communication over HTTP/HTTPS is performed via `libcurl`. MiniGit implements Git Transfer Protocol v1:
- **Packet Length Validation:** Every packet begins with a 4-byte hexadecimal length prefix. Non-hex characters are rejected with parse errors.
- **Boundary Checks:** Packets exceeding the standard Git pkt-line limit (65,520 bytes) or shorter than the 4-byte header (except for flush packet `0000`) are rejected.
- **Infinite Loop Safeguards:** Multi-packet parsing loops require monotonically advancing pointers.

### Packfile & Delta Decoder Hardening
- **Magic & Version Verification:** Packfiles must strictly match signature `PACK` with supported version 2.
- **Variable-Length Integer Guard:** LEB128-style variable-length integers and offset deltas check for shift overflow (capping bitshifts at 64 bits) to prevent integer truncation vulnerabilities.
- **Sliding-Window Delta Copy Clamping:** The delta copy instruction opcode validates offset + length against the base object's actual uncompressed size before memory writes occur, eliminating out-of-bounds heap reads/writes.
- **SHA-256 Checksum Verification:** The trailing 32 bytes of every `.pack` and `.idx` file contain the cryptographic SHA-256 digest of the preceding payload. Any single bit corruption causes `minigit verify-pack` and packfile loading to fail.

---

## 4. Cryptographic Hashing

MiniGit utilizes **SHA-256** exclusively via OpenSSL's EVP API (`EVP_DigestInit_ex`, `EVP_DigestUpdate`, `EVP_DigestFinal_ex`). 
- MiniGit does **not** rely on SHA-1 (eliminating SHAttered collision vulnerabilities present in legacy Git repositories).
- All content addressing (trees, blobs, commits, annotated tags) uses 256-bit hashes represented as 64-character lowercase hex strings.

---

## 5. What Remains Outside the Security Model

To ensure transparency with open-source reviewers and enterprise auditors:
- **Privilege Separation:** MiniGit runs with the privileges of the calling user.
- **Hook Execution:** MiniGit does not currently execute arbitrary server-side or client-side hooks, mitigating hook-injection vulnerabilities by design.
- **Transport Encryption:** Transport security over remote remotes relies on TLS/HTTPS provided by `libcurl` and system CA stores. Insecure plaintext HTTP is permitted if explicitly configured by the user, but HTTPS is standard.
- **Symlink Attacks on Non-POSIX Systems:** Symlink handling adheres to standard `std::filesystem` semantics; repositories containing circular symlinks are checked for depth limits during directory traversals.
