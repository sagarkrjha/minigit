# Community & Contributing

MiniGit is built collaboratively by open-source contributors around the globe. We welcome discussions, bug reports, feature suggestions, and pull requests.

---

## 1. Getting Involved

Here is how you can engage with the MiniGit ecosystem:

| Channel | Description | Link |
| :--- | :--- | :--- |
| **GitHub Repository** | Source code, continuous integration, and releases | [sagarkrjha/minigit](https://github.com/sagarkrjha/minigit) |
| **Issue Tracker** | Report bugs or request new features | [Issues](https://github.com/sagarkrjha/minigit/issues) |
| **Pull Requests** | Submit patches and documentation enhancements | [Pull Requests](https://github.com/sagarkrjha/minigit/pulls) |
| **Releases & Hashes** | Official pre-built assets and SHA-256 verification | [Releases](https://github.com/sagarkrjha/minigit/releases) |

---

## 2. Reporting Issues

When filing an issue, please include:
1. Your operating system and architecture (`Windows x86_64`, `Ubuntu 24.04`, `macOS arm64`).
2. MiniGit version (`minigit --version`).
3. Steps to reproduce the unexpected behavior.
4. Expected vs. actual command output.

---

## 3. Contribution Guidelines

We adhere to clear standard open-source conventions:
- **Code of Conduct:** Respectful, welcoming, and collaborative participation for everyone.
- **Commit Messages:** Follow conventional commit standards (`feat:`, `fix:`, `docs:`, `test:`).
- **Tests First:** Ensure corresponding test coverage accompanies new functionality or bug fixes.
- **License Integrity:** All contributions are provided under the project's [MIT License](/docs/about).
